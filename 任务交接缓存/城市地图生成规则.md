# 城市地图生成规则（任务交接）

一句话：把《自然语言蓝图》里"城市 = 区域排列的坐标网格"那套规则，生成**坐标网格城市图 PNG**，可单张、可批量。

---

## 1. 产物与位置

| 项 | 约定 |
|---|---|
| 输出目录 | `C:\Users\chair\Desktop\vibe-gaming\城市视图\` |
| 批量命名 | `城市-01.png … 城市-0N.png`（文件名**不许**带「东/南/西」这类中文后缀） |
| 手绘稿还原 | 单张 `城市地图.png`（1:1 还原，不许自行改结构） |
| 生成脚本 | `接入LLM的skills\生成类LLM\scripts\gen_maps.py` |
| 运行命令 | `python gen_maps.py --out "<输出目录>"` |
| 目录卫生 | 只留成品；改过的旧图直接覆盖，不留中间稿 |

## 2. 图面约定

- **1 格 = 1 个区域 = 1×1**；`居民区`、`位面传送门`、`宫殿` 例外，占 2×2。
- 横轴 `A B C …`，纵轴 `1 2 3 …`；每块左上角标坐标，2×2 标 `C1·2×2`。
- **门 = 深色竖条**（相邻且可达）；**墙 = 浅色横杠**（相邻但不可达）。两者都必须画出来，不能只画门。
- **`&` = 红色外框 + 共用边上的圆形徽标**，表示两块必须相邻合并。
- 配色七类：道路（灰蓝）/ 住宅（米黄）/ 商业·服务（橙）/ 公共设施（浅蓝）/ 公园绿地（绿）/ 位面传送门（粉）/ 宫殿（紫）。
- 右侧固定一栏：**图例**（含"门 / 墙 / &"三项解释）+ **本城要点**（骨架、网格、区域数/占地、数量统计、读图约定）；左下角写规则出处。

## 3. 区域清单与数量

| 类别 | 区域 | 占地 | 数量 |
|---|---|---|---|
| 骨架 | 道路 | 1×1 | 任意，但必须连成一张网 |
| 核心 | 位面传送门 | 2×2 | 唯一，放城心 |
| 住宅 | 居民区 | 2×2 | 2–3 |
| 住宅 | 家 | 1×1 | 唯一，挂路末 |
| 商业 | 酒馆 / 市场 / 城市公园 | 1×1 | 各 1–3 |
| 公共 | 冒险者协会&政府、魔法协会&科学协会 | 1×1 | 各 1 组 |
| 公共 | 教堂&墓地、公园&林地 | 1×1 | 各 1–2 组 |
| 公共 | 地标 | 1×1 | 唯一，靠中心 |
| 公共 | 宫殿 | 2×2 | 唯一，远离住宅 |

> 组 = `&` 对，两块必须相邻；数量按"组"计。

## 4. 硬规则（一条都不能漏）

1. 相邻且可达画**门**，相邻但不可达画**墙**，两类都要标注。
2. `&` 对必须**相邻且合并**：公园&林地、教堂&墓地、冒险者协会&政府、魔法协会&科学协会。
3. **每个区域至少与道路相邻，且至少有一处门**（`&` 对可借搭档的门）。
4. 数量按第 3 节区间，生成器自身要带随机（不写死上限）。
5. **不许出现 2×2 纯道路**（四格全是路面不好看）：把窗口里最靠几何中心的一格**删掉**（不新增任何区域类型），删完立刻复检道路仍连通；逐格试，四格都不行才保留并报错。
6. **道路必须是一整张网**：所有路面格（含传送门当路口）只允许 1 个连通块；生成期补最短连接路，出图前 BFS 断言，出现 `道路被割裂` 直接红灯。
7. **紧凑优先**：中心区不许大片空格（割裂感）。放置打分加 `occupied_neighbors × 1.3`；收尾用 `fill_with_roads()` 从已有道路伸 1 格短支路补洞，**只用道路，不许发明新区域类型**。
8. **不许自创区域类型**（例如「院子」「广场」「某区·东」）：类型只用第 3 节清单里的名字；同名可重复，但**不加方位后缀**。

## 5. 位置原则

- **位面传送门**：城心，2×2 吃满 4 格，四邻不放住宅（出门第一眼是路/市场）。
- **家**：某条路的**尽头**（该路格只有 1 个道路邻居），不在中心。
- **宫殿**：远离居民区（≥3 格），靠近公园/教堂。
- **公园、教堂**：走**路网末梢**，只连一条路，做成死胡同。
- **酒馆 / 市场 / 城市公园**：靠近居民区和家。
- **协会、政府、地标**：贴近城市中心。
- **居民区**：成片、彼此不贴脸，靠主干道。

## 6. 生成顺序（固定，别跳步）

1. 城心预留 2×2 给**位面传送门**；
2. 铺**路网**骨架（`cross` 十字 / `double` 双横街 / `comb` 梳状 / `h` 井字 / `ring` 环城路），可加 2–3 格短支路；
3. 放**居民区 → 家 → 酒馆/市场/城市公园 → 地标**；
4. 放四组 **`&` 对**；
5. 最后放**宫殿**；
6. 补洞、连边、校验、出图。

## 7. 校验清单（必须全绿才出图）

- [ ] 每个区域 ≥1 个门（`&` 对可借搭档）
- [ ] 全图连通：从传送门能走到任意区域
- [ ] 四组 `&` 对相邻且都画了徽章
- [ ] 2×2 只有居民区 / 位面传送门 / 宫殿；**无 2×2 纯道路**
- [ ] **道路是单一连通块**（传送门算路口）
- [ ] 中心区（半径 2）只有 1–3 个单格细巷口，没有连片空白
- [ ] 数量在区间内；传送门在城心；家挂路末；宫殿离住宅 ≥3 格
- [ ] 相邻但未连线的对，全部画了墙
- [ ] 图例含"门 / 墙 / &"，文件名无中文后缀，目录无中间稿

## 8. 已知取舍（别再当 bug 修）

- 中心偶尔剩 1–3 个**单格细巷口**：紧贴主路的竖缝若用道路填，必然长出 2×2 纯道路，与规则 5 冲突 → 允许保留，只打印提示。
- **传送门是路口**：四邻全开门，不作为"被切断的道路"。
- **同名区域可重复**（两个「市场」、两个「城市公园」），属于数量区间的正常结果，不许改名区分。

## 9. 被用户明确否掉的做法（勿重犯）

1. 自创「院子 / 广场」等区域类型来填洞 → 已全部删除。
2. 出现 2×2 纯道路 → 现在改成"删一格 + 复检连通"。
3. 路网割裂、有断路 → 现在有 BFS 单连通断言。
4. 给区域编方位后缀（`酒馆·东`）或凭空加一整排路 → 手绘稿还原时必须 1:1。
5. 输出 PPT / 概念美术图 → 用户只要坐标网格 PNG。
