# 城市地图生成器（蓝图 → 坐标网格视图）

把文本规则变成一张"人能看懂、机器也能吃"的城市布局图。
产物是**一张 PNG + 一份矩阵文本**，而不是概念图或美术设定稿。

## 什么时候用

- 用户给了区域清单、"必须相邻""至少一门接路"这类规则，要一张布局图。
- 用户画了草稿，要转成电脑图（要求 1:1 还原，不要自作聪明改结构）。
- 用户要"再来 5 座类似的城市"，规格可自定。

**不要**用来做：3D 场景/建筑美术、剧情文本、数值平衡表。

## 输入

| 输入 | 必需 | 说明 |
|---|---|---|
| 区域清单 | 是 | 每个区域的名字、占地（默认 1×1，特例 2×2）、功能分类 |
| 相邻规则 | 是 | `-` 可达相邻、`&` 必须相邻合并、以及"每区域至少一门接路" |
| 数量/位置规则 | 是 | 例如"居民区 2–3""传送门在城心""家挂路末" |
| 手绘草图 | 否 | 有则必须 1:1 还原，见"还原草图"一节 |
| 规模 | 否 | 列数×行数，未给时按区域数估算（区域数 ≈ 列×行×0.45） |

## 输出

1. `城市地图.png` —— 坐标网格视图，带坐标轴、图例、门/墙图例、& 徽章。
2. `城市矩阵.txt` —— I 矩阵数字表 + 门方向表 + `&` 合并表（见 `reference/矩阵格式.md`）。
3. 终端校验输出 —— 每个城市的区域数、占地、数量统计、`checks OK`。

批量生成时：`城市-01.png … 城市-0N.png`，**不要**在文件名里塞中文后缀（`酒馆·东` 这类用户会反感）。

## 十条硬规则（来自蓝图，必须全中）

1. 网格基本单位 1×1；`居民区`、`位面传送门`、`宫殿` 占 2×2，其余 1×1。
2. 相邻且可达 = **门**；相邻但不可达 = **墙**。两者都要画出来，不能只画门。
3. `&` 对必须相邻合并：公园&林地、教堂&墓地、冒险者协会&政府、魔法协会&科学协会。
4. **每个区域至少与道路相邻，且至少有一处门**（`&` 对可借搭档的门）。
5. 数量：居民区 2–3；公园&墓地 1–2；酒馆 / 城市公园 / 市场各 1–3；其余唯一。
6. 位面传送门放城心；宫殿 2×2 远离住宅、靠近公园/教堂。
7. 公园、教堂走**路网末梢**（只连一条路，做成死胡同）。
8. 居民区与家带住宅属性；酒馆 / 市场 / 城市公园靠近它们。
9. 协会、政府、地标贴近城市中心。
10. 生成顺序：**先定位面传送门 → 再铺路网 → 最后按优先级填充**。

## 我补充的十条原则（可删改，仅供参考）

1. **先轴后点**：先生成 2 条主轴（横 + 纵），其余区域都是挂在轴上的叶子；比随机撒点更像城市。
2. 2×2 的块必须吃满 4 格，四边不留 1 格宽的碎缝（否则玩家以为是路）。
3. `&` 在数据里存成"一个区域、两个子标签"，不要存成两个独立区域，否则数量统计会算错。
4. 门数控制：普通区域 1 门；交通型（路 / 市场 / 传送门）2–4 门。门多的区域会被当成走廊而不是目的地。
5. 家 → 路末；宫殿 → 距任何住宅 ≥3 格；公园/教堂 → 只连一条路。
6. 传送门 4 邻不要放住宅：出门第一眼要是广场 / 市场 / 道路。
7. II 类矩阵尺寸跟区域等级走：公园/林地/宫殿 3（大）、市场/协会 2（中）、家/酒馆 1（小）——写进"AI 预训练"参数表。
8. 不可达的相邻也要有"墙"的视觉，否则玩家会一直往那边撞。
9. 数量留档：2–3 而不是写死 3，生成器本身要带随机。
10. 一城一标志物（宫殿或地标），其余保持同构——多城市迁移时既有差异又能复用规则。
11. **不许出现 2×2 纯道路**：四格都是路面的方块不符合人类审美。做法是把窗口里最靠几何中心的一格**直接删掉**（不新增任何区域类型），删完立刻复检道路仍连通；逐格试，四格都不行就保留窗口并报错。
12. **紧凑优先**：空地在中心区大量出现会造成割裂感。放置打分统一加 `occupied_neighbors * 1.3` 的紧凑偏好；收尾用 `fill_with_roads()` 从已有道路伸出 1 格短支路把洞吃掉（只用「道路」，不许发明新区域类型），加之前先确认不会凑出 2×2 纯道路。
13. **道路必须是一整张网**：所有路面格（含位面传送门当路口）只允许 1 个连通块。生成期按需补最短连接路，出图前 BFS 断言，出现 `道路被割裂` 直接红灯。

## 工作流（五步，别跳步）

1. **拆规则**：把输入的每条规则翻译成"可判定的断言"（见 `reference/校验清单.md`）。判不了的规则先问，不要猜。
2. **搭骨架**：选一种路网模式并写明为什么用它：
   `cross`（十字）/ `double`（双横街）/ `comb`（梳状）/ `h`（井字）/ `ring`（环城路）。
3. **放区域**：按优先级 + 打分函数放置，顺序固定为
   居民区 → 家 → 酒馆/市场/城市公园 → 地标 → 四组 `&` 对 → 宫殿。
   每个候选点都要求"至少邻一条路"，否则直接弃用。
4. **连边与校验**：道路之间全连通；每个非道路区域连一条最近的路；`&` 对内部相连。
   跑 `validate()`，**必须输出 `checks OK` 才能出图**。
5. **出图**：套 `reference/视觉规范.md`，图右侧固定放"图例 + 本城要点"，左下角写规则出处。

## 校验清单（出图前逐条确认）

- [ ] 每个区域都有 ≥1 个门；`&` 对允许借搭档
- [ ] 全图连通（从传送门出发能到任意区域）
- [ ] 四条 `&` 对全部相邻且都画了徽章
- [ ] 2×2 只有居民区 / 传送门 / 宫殿三类；**没有 2×2 纯道路**
- [ ] 中心区（半径 2）没有连片空格；空洞只能用短支路补，不许新增区域类型
- [ ] **道路是单一连通块**（含传送门当路口），没有割裂的断路
- [ ] 数量在蓝图区间内
- [ ] 传送门在城心；宫殿离住宅 ≥3 格；家在地图边缘的路末
- [ ] 相邻但未连线的对，全部画了墙
- [ ] 图例含"门 / 墙 / &"三个解释项
- [ ] 文件名无中文后缀、目录里不留中间稿

## 还原草图（有手绘稿时的唯一正确姿势）

用户一旦说"照我的图来"，**结构就不许改**。

1. 给原图叠 100px 坐标网格（500px 加粗），放大 1.35~2 倍分上下两半读。
2. 二值化后对"纸面空洞"做连通域标记，拿到每个方块的精确中心与尺寸；
   再在图上打索引号逐块核对文字。
3. 手写体要放大 4–6 倍 + autocontrast + sharpen 才读得准。
4. 重复名字（三个"居民区"、两个"市场"）**保持原名**，用坐标角标区分，不要编后缀。
5. 读不准的字：按蓝图词表填最接近的，并在回复里单独点名让用户确认。

## 视觉规范速览

| 元素 | 做法 |
|---|---|
| 底色 | 暖白 `#F6F3EC`，格线 `#E4DED2` |
| 区域块 | 圆角 12（道路 8），按功能填色，描边 1px 黑 transparent-28 |
| 功能色 | 道路灰蓝 / 住宅暖黄 / 商业橙 / 公共蓝 / 公园绿 / 传送门粉 / 宫殿紫 |
| 门 | 深色条（`#788494`），画在两块公共边上，宽 0.3 格 |
| 墙 | 浅色横杠（`#C6BEB0`），长条端点缩进 6px |
| `&` | 红框（`#C66060`）+ 共用边中点圆形徽章 |
| 坐标 | 列 A/B/C…，行 1/2/3…，块左上角写 `E5·2×2` |
| 字号 | 标题 44、区域名 26（>4 字用 21）、注释 15、图例 18 |

细节与配色常量见 `reference/视觉规范.md`。

## 常见错误（都踩过）

- **随机删道路格做"街区"** → 把路网打断，出现 `不连通`。要加支路，不要删格。
- **`&` 对只检查一个成员临街** → 校验会误报"未接路"。校验函数要对搭档放行。
- **对固定尺寸的面板调用"拉伸铺满"** → 子元素全挤到左上角（UI 同类坑）。
- **给区域编后缀名**（`酒馆·东`）→ 用户认不出这是他的字。
- **把整图缩小后凭感觉读坐标** → 误差可达 1.7 倍。必须叠网格。
